# Phase 3 — UI Design Contract

> Visual and interaction contract for the contact form page. SEO, security, and image optimization in this phase are invisible infrastructure with no new visual components. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Field-level error message margin, compact element spacing |
| md | 16px | Form field vertical gap, input padding |
| lg | 24px | Section padding, form-to-info column gap on mobile |
| xl | 32px | Contact details block spacing |
| 2xl | 48px | Major section breaks (form area to FAQ section) |
| 3xl | 64px | Page-level vertical padding (py-16 md:py-24 pattern) |

Exceptions: Form inputs use 12px horizontal padding (px-3) and 10px vertical padding (py-2.5) for comfortable touch targets at 44px minimum height. This is consistent with the existing Button component padding pattern.

Source: Established patterns from Phase 1-2 components (py-16 md:py-24 section padding, p-8 card padding, mb-6 heading margins).

## Contact Page Layout Contract

### Desktop (lg and above, 1024px+)

```
+----------------------------------------------------------+
| Header (existing)                                         |
+----------------------------------------------------------+
|                                                           |
|  +------------------------+  +-------------------------+ |
|  | H1: Meer weten?        |  | Form heading            | |
|  | Plan een adviesgesprek.|  | [Name field]            | |
|  |                        |  | [Email field]           | |
|  | Description paragraph  |  | [Company field]         | |
|  | Sub-description        |  | [Message textarea]      | |
|  |                        |  | [Verstuur bericht]      | |
|  | --- Contact Details ---+  +-------------------------+ |
|  | Phone: 020 308 68 40   |                              |
|  | Email: info@honeylink.nl                              |
|  | Adres: Marco Polo...   |                              |
|  | KvK: 96561556          |                              |
|  | BTW: NL005216613B11    |                              |
|  +------------------------+                              |
|                                                           |
+----------------------------------------------------------+
| FAQ Section (full width, bg-brand-gray-light)             |
| "Veelgestelde vragen." + 5 accordion items                |
+----------------------------------------------------------+
| Footer (existing)                                         |
+----------------------------------------------------------+
```

- Two-column grid: `grid grid-cols-1 lg:grid-cols-2 gap-12`
- Left column: 50% width, contains heading, descriptions, contact details
- Right column: 50% width, contains the form card
- Container: `mx-auto max-w-7xl px-4 py-16 md:py-24`
- Form card: white background, rounded-2xl, p-8, shadow-sm border border-gray-100

### Mobile (below lg, < 1024px)

- Single column stack: heading and description first, then contact details, then form
- All content stacks vertically with 32px (gap-8) between sections
- Form card fills full width with p-6 padding (reduced from p-8)

### Form Field Pattern

Each form field follows this structure:

```html
<div class="mb-4">                                   <!-- 16px bottom margin -->
  <label class="block text-sm font-accent font-medium text-brand-black mb-1.5">
    Label text
  </label>
  <input class="
    w-full px-3 py-2.5                               <!-- full width, comfortable padding -->
    bg-brand-gray-light                              <!-- light gray background -->
    border border-gray-300                           <!-- subtle border -->
    rounded-lg                                       <!-- consistent with Button rounding -->
    text-base text-brand-black                       <!-- body text style -->
    placeholder:text-brand-gray-dark                 <!-- muted placeholder -->
    hover:border-gray-400                            <!-- hover feedback -->
    focus:outline-none focus:ring-2 focus:ring-brand-purple focus:border-transparent
    transition-colors duration-200                   <!-- smooth state transitions -->
  " />
  <!-- Error message (conditional) -->
  <p class="mt-1.5 text-sm text-red-600">Error text</p>
</div>
```

- Message field uses `<textarea>` with `rows="5"` and `resize-y` class
- Company field shows "(optioneel)" after the label in text-brand-gray-dark font-normal
- Submit button: full width on mobile (`w-full lg:w-auto`), variant="primary", size="lg"

### Success State

When form submits successfully, the form card content is replaced with:

```html
<div class="bg-green-50 border border-green-200 rounded-2xl p-8 text-center">
  <!-- Checkmark icon (inline SVG, 48px, text-green-600) -->
  <h3 class="font-heading text-xl font-bold text-green-800 mt-4">
    Bedankt voor uw bericht!
  </h3>
  <p class="text-green-800 mt-2">
    We nemen zo snel mogelijk contact met u op.
  </p>
</div>
```

### Error States

**Field-level validation errors:** Red text below the offending field. Input border changes to `border-red-500`. Input background stays `bg-brand-gray-light`.

**Server error (email delivery failure):** Banner above the form fields:

```html
<div class="bg-red-50 border border-red-200 rounded-lg p-4 mb-6">
  <p class="text-red-600 text-sm font-medium">
    Er is iets misgegaan bij het versturen. Probeer het later opnieuw.
  </p>
</div>
```

**Rate limit error:** Yellow warning banner above the form fields:

```html
<div class="bg-yellow-50 border border-yellow-200 rounded-lg p-4 mb-6">
  <p class="text-yellow-800 text-sm font-medium">
    Te veel verzoeken. Probeer het over een uur opnieuw.
  </p>
</div>
```

### Loading State

Submit button during form submission:
- Text changes to "Versturen..."
- Button becomes `disabled` with `opacity-50 cursor-not-allowed`
- Uses superforms `$delayed` store (activates after 500ms to avoid flicker)

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Form field focus | Purple ring (ring-2 ring-brand-purple), border transparent, 200ms transition |
| Form field hover | Border darkens from gray-300 to gray-400, 200ms transition |
| Form field with error | Border red-500, error text visible below field |
| Form field error clears | Error text and red border removed when user starts typing (superforms auto-clears on input) |
| Submit button hover | bg-brand-black to bg-brand-purple transition (existing Button primary hover pattern) |
| Submit button disabled | opacity-50, cursor-not-allowed, no hover effect |
| Success message appears | Form card content replaced. No page redirect. Scroll position maintained. |
| Success message fade-in | opacity-0 to opacity-100, 300ms ease-out transition |
| FAQ accordion toggle | Existing FaqItem pattern: chevron rotates 180deg, content slides open via max-height transition, 300ms ease-out |
| Scroll animation | Contact info and form sections use existing `inview` action for fade-in on scroll (opacity-0 translate-y-4, 700ms ease-out) |

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Form labels | Every input has a visible `<label>` element linked via `for`/`id` attributes |
| Required fields | Name, email, message have `required` attribute via superforms `$constraints` |
| Error announcement | `aria-invalid="true"` on inputs with errors, `aria-describedby` pointing to error message `<p>` element |
| Error summary | Screen readers can navigate to individual field errors via `aria-describedby` |
| Submit button | `<button type="submit">` with disabled state reflected in `aria-disabled` |
| Focus management | After successful submission, focus moves to the success banner heading |
| Color contrast | All text meets WCAG AA: brand-black (#000) on white = 21:1, brand-gray-dark (#3b3b3b) on white = 10.7:1, red-600 (#dc2626) on white = 4.6:1 |
| Touch targets | All interactive elements minimum 44px height (inputs: py-2.5 + text = ~44px, button: py-4 in lg size) |

## SEO Visual Contract

SEO and security work in this phase is invisible infrastructure. No new visual components are needed. The following items produce no visible UI changes:

- MetaTags component renders in `<head>` only (no visible output)
- JsonLd structured data renders as `<script type="application/ld+json">` in `<head>`
- sitemap.xml is a server endpoint returning XML
- robots.txt is a static text file
- CSP headers are HTTP response headers
- Enhanced-img changes image `src` attributes and adds `srcset`/`sizes` but preserves existing visual appearance
