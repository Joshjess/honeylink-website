**Create `Dockerfile`** (multi-stage build per D-03):

```dockerfile
# Stage 1: Build
FROM node:22-alpine AS build

WORKDIR /app

# Copy package files first for layer caching
COPY package.json package-lock.json ./

# Install all dependencies (including devDependencies for build)
RUN npm ci

# Copy source code
COPY . .

# Build the SvelteKit app
RUN npm run build

# Prune dev dependencies
RUN npm prune --production

# Stage 2: Production
FROM node:22-alpine AS production

WORKDIR /app

# Copy built output and production node_modules
COPY --from=build /app/build ./build
COPY --from=build /app/node_modules ./node_modules
COPY --from=build /app/package.json ./

# Set environment defaults
ENV NODE_ENV=production
ENV PORT=3000

# Expose port
EXPOSE 3000

# Health check
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:3000/ || exit 1

# Run the SvelteKit server
CMD ["node", "build/index.js"]
```

Key decisions in this Dockerfile:
- `node:22-alpine` for small image size (Node 22 LTS)
- Two stages: `build` installs all deps + builds, `production` only has runtime deps + build output
- `npm prune --production` removes devDependencies before copying to production stage
- HEALTHCHECK uses wget (available in alpine) to ping the homepage
- Entry point is `node build/index.js` (SvelteKit adapter-node output)

**Create `docker-compose.prod.yml`** (Coolify-compatible per D-01, D-02):

```yaml
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
    restart: unless-stopped
    environment:
      - NODE_ENV=production
      - PORT=3000
      - ORIGIN=${ORIGIN:-https://honeylink.nl}
      - RESEND_API_KEY=${RESEND_API_KEY}
    expose:
      - "3000"
    networks:
      - web
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost:3000/"]
      interval: 30s
      timeout: 5s
      start_period: 10s
      retries: 3

  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
      - "443:443/udp"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    networks:
      - web
    depends_on:
      app:
        condition: service_healthy

volumes:
  caddy_data:
  caddy_config:

networks:
  web:
    driver: bridge
```

Key decisions:
- `restart: unless-stopped` per D-09/D-10 (replaces PM2)
- `app` service uses `expose` (internal only), not `ports` -- Caddy handles external traffic
- Caddy depends on `app` being healthy before starting to proxy
- `caddy_data` volume persists Let's Encrypt certificates across restarts
- `443:443/udp` enables HTTP/3 (QUIC) support
- Environment variables use `${VAR}` syntax for Coolify to inject

**Create `Caddyfile`** (per D-07, D-08):

```
honeylink.nl, www.honeylink.nl {
	reverse_proxy app:3000

	encode gzip zstd

	header {
		Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
		X-Content-Type-Options "nosniff"
		X-Frame-Options "DENY"
		Referrer-Policy "strict-origin-when-cross-origin"
		Permissions-Policy "camera=(), microphone=(), geolocation=()"
	}

	handle_errors {
		respond "{err.status_code} {err.status_text}"
	}
}
```

Key decisions:
- Both `honeylink.nl` and `www.honeylink.nl` handled (Caddy auto-provisions certs for both)
- `encode gzip zstd` for response compression
- HSTS header with preload flag for maximum HTTPS security
- Security headers duplicated from hooks.server.ts at the proxy level for defense-in-depth (Caddy adds them to ALL responses including static files; SvelteKit hooks only cover SSR responses)
- `handle_errors` provides clean error pages
- Caddy automatically provisions and renews Let's Encrypt certificates (zero config per D-08)
